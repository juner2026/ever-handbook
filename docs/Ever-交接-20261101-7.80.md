### E 的根因（这次真找到了）

树上的吊牌是 `position:absolute; left/x% ; top/y%` + `transform: translate(-50%,-50%)`。
真机点击时：

- `pointerdown` 的 target 是吊牌里的 `<svg>`（正常）；
- 但 `click` 的 target 落到了 **祖先 `.m2tree` / `.grid-s` 那一层** ——
  桌面文档的导航桥 `findNav(e.target)` 从 `e.target` 往上找 `data-open`，于是拿到 null，
  **根本没有 postMessage**，App 那边自然「点不进去」。
- 用 `element.click()` 能进，所以以前的自动化测试一直是绿的，真机才炸。

修法（`_mobile/patch/round-7.80/apply.py` 写进 jh-doc）：

```js
/* 点在树里、但 target 没落到吊牌上时：取离点击点最近的吊牌（52px 内），按它的 data-open 发 jh:nav */
document.addEventListener('click', function(e){ ... nearest .cell2 ... }, true);
```

## 7. 这轮的坑（写下来免得下次再踩）

1. **`element.click()` 绿不等于真机绿**：导航桥按 `e.target` 找 `data-open`，
   而带 `translate(-50%,-50%)` 的吊牌真机点击时 target 会落到祖先层。
   以后测桌面入口，一律用**坐标真实点击**（`page.mouse.click(cx,cy)`）或 Playwright 的 locator click。
2. **`scroll-snap` 的 track**：`track.scrollLeft = 752` 会被吸回 740（max），算坐标要用回读值。
3. **`tfsPanel()` 每 2.5s 自愈**：它原来把卡片插在 `pg` 里、靠 `.sb-group` 定位；
   换皮时必须一并改 host，否则会出现「旧样式文件卡」挂在页面最下面。
4. **改壳子的样式别再叠 `!important` 战场**：工作区新样式全部走 `#p-work .wkw-*` 新类名，旧类名一条没碰。
5. **改 JS 字符串里的换行别手滑**：往 shell.html 里拼 `...</div>';` 时写成 `'...\n'`（字面反斜杠 n）会让整段脚本
   `Unexpected token`，页面能开但一整块逻辑静默不跑。改完必须 `new Function(每个 script)` 过一遍。
6. **「只改手机版」的判据要和文档一致**：文档用 `min(宽,高) >= 560` 判平板；只查 `data-mh` 不够，
   mh 在 boot 早期可能还是旧值，装饰件会提前被改掉。判据写 `data-mh` + `Math.min(innerWidth, innerHeight)`。
7. **一套组件只写了一种布局的皮**：`.m2-bub` 全部挂在 `html[data-mh="phone"]` 下，
   平板布局（`data-mh=tablet`）里它就退化成裸 div —— 定位、背景、描边全没有。
   以后凡是「手机布局里才建的装饰件」，要么在平板里别建，要么把皮一起补上。
