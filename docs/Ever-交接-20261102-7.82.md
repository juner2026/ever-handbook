## 一、这一版改了什么（接 7.81 之后用户报的两条）

| # | 用户原话 | 根因 | 改法 |
| --- | --- | --- | --- |
| 1 | 「全屏之后点聊天页的聊天框，再退出聊天框会黑屏闪一下」 | 键盘弹起/收起只改视口高度，但 `resize` 会把**整本桌面 iframe** 重排三次（`relayout()` → `layout()` ×4；开屏收尾的 `relayoutDesk()` 又补两次）。桌面是 4.2MB 的内联文档，重排一次黑一帧 | 新增 `kbOnlyResize()`：**宽度没变 + 高度一次变化 >140px = 键盘**，直接不重排；再配 `__teKbHoldUntil`（命中后 3 秒内所有重排让路，覆盖 `relayout` / `check()` 600ms 轮询 / `relayoutDesk` / `jh:splash-done` 补排）。地址栏那种 40~100px 的小变化仍照常重排（6.41 的修复没丢） |
| 2 | 「那个图片，时而大时而小，会一直闪，统一改为小」 | 聊天图只有 `max-width/max-height` + `width:auto`：图还没解码时盒子是 2×2，解码完跳到 110×145；每条消息重绘都再跳一次 | CSS 给固定 **96×96** 盒子（`object-fit:cover`、圆角 6px），加载前后同一个盒子；JS 里每 3 秒扫一遍的 `_forceImgSize` 改成同一组数字（原来写 110/145，会和 CSS 打架）。表情包 96 但 `contain`（不裁透明边），明信片卡（`data-imgkey^=tepc_`）不动 |

实测（无头 Chromium 430×932）：

- 键盘式改高度 `932 → 602 → 932`：`#jh-home` 尺寸**一直是 932px，`layout()` 调用 0 次**（改前 3 次）
- 三张不同比例的图：0.3s 和 3.5s 时都是 `96x96 / 96x96 / 96x96`（改前 2×2 → 110×83 / 74×145 / 110×110）
