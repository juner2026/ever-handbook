## 二、7.99：桌面不再因为一帧的视口抖动换整套排版

上面那条日志暴露了一件事：**只要桌面 iframe 的 innerWidth 某一帧 ≥ 560**，
`m2-apps.js` 的 `autoMh()` 就会把整本手帐切成平板排版（`data-mh/data-view="tablet"`），
下一帧再切回来 —— 整本 13 万行重排两次。平板版和手机版的纸页位置完全不同，
"整个画面弹动、纸页跑到右下角再回来"和这个现象对得上。

改法：

1. 手机上（外壳 `__tePhoneLock` 或 `localStorage['te-force-phone']`）
   **永久钉成 phone**，不再看视口大小；
2. 其它环境：候选模式要**连续两次一致（间隔 ≥ 350ms）**才真的切，
   一帧的抖动过不了这一关；
3. 每次切换记进 `window.__mhLog`（最多 20 条），方便以后核对。

实测（人为把盒子改成 860×1864，即制造那种"一帧变宽"）：

```
初始      {"mh":"phone","view":"phone"}
变宽160ms {"mh":"phone","view":"phone"}
变宽760ms {"mh":"phone","view":"phone"}   ← 改前这里会变成 tablet
__mhLog: [{"cand":"phone","cur":"tablet","applied":0}]   ← 候选被压住了
```

# 补：8.01（2026-11-02 · 0938 之后）—— 弹动真凶

> 版本：**`8.01-20261102-0938-mobile`** · **17,107,294 字节** · sha256 前 16 `121d60a8cdca1ba6`

**用户手机上的 `?diag=1` 打点回来了**（`_diag.log`，09:34 那条）：

```json
{"dpr":2.9486,"vw":700,"vh":413,"sw":1050,"sh":700,"vv":[700,413,1.5],"zoom":"1",
 "ua":"...Android 16; PA2573 ... wv) ... Version/4.0 ..."}
```

`screen` 报 **1050×700**（短边 700 > 560）→ 这台机被当成"平板"：

1. `__teLockPortrait` 的 `PHONE` 判成 **false**，`?phone=1` 白写；
2. tbFit 走"横屏平板"：`s = min(1050/600, 1.5) = 1.5` → `setMeta('width=700,initial-scale=1.5')`
   （正好对上 innerWidth=700 / 页面 scale=1.5）；
3. `appScale()` 读 meta 的 initial-scale = **1.5** → `layout()` 写 `width=1050 + scale(0.667)`；
4. tbFit 里还有一条"meta 没生效就退回 zoom"的校验，回退又会改 innerWidth → resize → 再 apply()。

→ **两套缩放机制（meta initial-scale ↔ CSS zoom）在同一个视口上拉锯**，每切一次整页重排，
就是"整个画面弹动"。

**8.01 改法（全部围绕"`?phone=1` 就当 1:1 手机版"）**：

| 位置 | 改动 |
| --- | --- |
| `__teLockPortrait` | `?phone=1` / `te-force-phone` → `PHONE=true`，且 `OFF=true`（不做冻结竖屏） |
| tbFit `apply()` | `?phone=1` → 直接 `setMeta(BASE); setZoom(1); mode='off'`，不进平板分支 |
| `appScale()` | `?phone=1` → 直接返回 `{s:1, zoom:false}` |
| tbFit meta↔zoom 兜底 | 2 秒内切换超过 2 次 → 彻底停用缩放（防拉锯） |

**实测（无头）**：

```
竖屏: rect[0,0,430,932] transform scale(1) meta=初始值 zoom=1 phoneLock=true lockOff=true mh=phone
横屏: rect[0,0,932,430] transform scale(1) 同上（不再缩成 0.59 居中小块）
回竖: rect[0,0,430,932] 稳定，tbFlip=null（一次都没触发防抖）
```

`smoke`、气泡一致、`#jh-home` 样式写入 0 次 全部照旧通过。

回滚：`python3 _mobile/patch/round-801/apply.py --revert`

## 8.04：真凶

真机 + 浏览器回传里抓到这条（同一页面每几秒一次）：

```
d {"pg":[[525,351,1050,577],[0,42,1050,577]]}     ← 页面从"半屏处"跳回左上
d {"pg":[[0,42,1238,649],[619,388,1238,649]]}     ← 又跳到半屏处
d {"pg":[[619,388,1238,649],[0,42,1238,649]]}
```

`525 = 1050/2`、`619 = 1238/2` —— 页面左边缘正好落在 **50%**，就是用户截图那个样子。
两套 CSS 撞了：

```css
html[data-fit="1"] .app{ width:1180px;height:760px;position:fixed;top:50%;left:50%;
                         transform:translate(-50%,-50%) scale(var(--fit,1)); }   /* 平板预览 */
html[data-mh="phone"] .app{ width:100%!important;height:100dvh!important;
                            transform:none!important }                            /* 手机版：把居中抹了 */
```

`data-fit="1"` + `data-mh="phone"` 同时成立 → `.app` 钉在 50%/50%、宽 100% → 页面跑到右下半屏。

而 `data-fit` 被两处代码来回写：

- 外壳 `teForcePhone`（`?phone=1`）：`60/200/600/1200/2400/4000ms` + 每次 resize 都写 **"1"**；
- 桌面 `applyLayout()`（resize 时跑）：手机模式写 **"0"**。

→ 拉锯，每切一次跳一下。

**改法（两处）**：

1. `?phone=1` 是"强制手机版"，`data-fit` 写 **"0"**（`1` 是"小屏看平板"，方向正好相反）；
2. 桌面 CSS：`html[data-mh="phone"] .app` → `html[data-mh="phone"]:not([data-fit="1"]) .app`，
   以后谁再把 fit 打开也不会再出现"钉在 50%/50%"（那时会变成居中的 1180×760 画布）。

**实测（模拟那台机 700×413 / screen 1050×700）**：

```
t0      fit=0 mh=phone app[0,0] appT=none pg[0,42]
点1~点4 同上（不再跳）
强行切 data-fit=1/0 各两次：fit 始终回到 0，pg 始终 [0,42]
```

`smoke`、气泡一致、`#jh-home` 样式写入 0 次 全部通过。
