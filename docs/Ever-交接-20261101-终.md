## 二、动效为什么「全废了」

这轮为了消掉「离谱动效」，删的东西比该删的多，具体清单：

| 被删/被压的动效 | 位置 | 怎么恢复 |
| --- | --- | --- |
| 吊牌弹跳 `@keyframes m2pop` | `_mobile/patch/round-7.80/apply.py` 里「2. 桌面大树吊牌」 | 重新加 keyframes + `.m2pop` 规则（建议 160–220ms、scale .96） |
| 吊牌 `:active` 缩放与 transition | 同上 | 给 `.sb-rooms .cell2` 加 `transition:transform .12s` + `:active{scale .98}` |
| 回桌面淡入 | 原 `#jh-home{transition:opacity .2s}` | 给 `#jh-home` 加 `transition:opacity .18s`，并在 nav 里加/移除 `opacity:0` 类 |
| 页面切换 `pgFade` | shell 原有 `#p-star{transition:...}` 被改 | 把 `html body #p-star{...}` 里对应 `!important` 去掉 |
| `.sb-rooms .cell2` 自身入场/按下动画 | 我在 jh-doc 里加过 `transform:translate(-50%,-50%)` 覆盖 | **已删**（这版不覆盖了，原生动画回来了） |

> **实测复核（2026-11-01 17:49 版）**：桌面 iframe 的 `documentElement.className = "scrapbook jh-splash-ready ts-done"`（**没有 `fitpage`**），
> `.page.on .rise` 的 `transition` 还在：`opacity 0.26s cubic-bezier(.23,1,.32,1) 0.204s / transform 0.3s ...`，带 68ms 递增延迟。
> 也就是说桌面入场动画是活的。
>
> 结论：**桌面原有的动画（`.rise` 入场、珍珠浮动、页面淡入）没有被删**，被删的是我给吊牌额外加的那套 + 回桌面过渡。如果真机上「全都动不了」，优先怀疑：
> 1. 还在吃旧缓存（一定带 `?v=7.80-20261101-1749`）；
> 2. 系统开了「减弱动态效果」（`prefers-reduced-motion`）；
> 3. `#p-star` / `#jh-home` 上残留的 `transition:none !important`（这版已清，可 `grep -c "transition:none"` 复核）。

## 三、已知未解问题

### 1. 移动方向相反（用户："往左移，好像往右移"）

- **无头实测聊天窗拖拽方向是对的**：左拖 100px，窗口 `x` 从 148 → 48，`HQ.off.x=-100`。
- 所以真机上如果相反/不跟手，问题在**外层缩放比 `k`**：`hqDragWire()` 里是
  `off.x = base.x + (ev.clientX - sx) / k;`
  （`_mobile/src/shell.html` 的 `hqDragWire`，约 52411 行）。
  真机若是 CSS `zoom` 放大（`appScale()` 返回 `zoom:true`），`clientX` 是布局像素、`translate` 是视觉像素，
  两者比例反了就会「拖左走右」。改法：把 `/k` 换成 `*k`，或直接用
  `(ev.clientX - sx)` 不除缩放，然后 `hqClampPos()` 兜底。
- 如果相反的是**人物在房间里走**（点左边走到右边），那不是这条，是
  `aset/home4/editor.html` 的 `toCanvas()`（`(px-view.ox)/view.s`）—— 那边要用 `view.dpr` 校正。

### 2. 回桌面的「放大/错位残影」

- 已确认是 **WebView 合成层**问题：DOM 里 `#jh-home` 已经 `display:none`，那一帧仍会被画出来。
- 无头逐帧：返回后约 40ms 间隔交替出现「正常 / 放大」两种帧（像素差 ~43k）。
- 唯一可靠方案（未实施）：**切页瞬间贴一张桌面静态截图，200ms 后换成真实桌面**。

### 3. 家园横屏

- 已撤。要横屏请**不要**用 `requestFullscreen()`（安卓 WebView 必带黑闪），改用
  「canvas 旋转 90° + 等比缩放塞进竖屏」，或干脆接受竖屏。

### 4. 设置页换壁纸「不明显」

- 已改：`has-setwp` 时 `.st2-veil` 由 `.97/.87/.85` → **`.93/.52/.46`**，
  `.set-overlay` `.62` → **`.16`**，`.set-bg` blur `3px` → **`1px`**。
- 若仍不明显，检查 `pickSetWp()`（约 20613 行）是否真的把 `has-setwp` 加到 `#p-set` 上。
