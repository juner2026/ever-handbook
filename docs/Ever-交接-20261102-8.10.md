## 1. 未解决的问题（优先级最高）

### 症状

用户两次截图一致：整页最上面是那张「Ever / 手帐 JOURNAL / 把平凡的日子慢慢写成喜欢」
纸卡，**只占屏幕左上角约 1/4**，其余全白；底部有一条 toast「没给定位权限，天气改用网络大致位置」。
一直是这个状态，不是一闪而过。

### 已经确认的事实

1. **手机上没装 APK** —— `com.tidalecho.app` 在应用列表里查不到（`/app/launch` 返回 NOT_FOUND）。
   所以这两张截图都是**网页**（浏览器或内置 WebView）的画面，不是 APK 的问题。
2. 页面的 `#jh-home` 是 `position:fixed;inset:0` 的整屏盒子，正常时 rect 必须等于视口。
3. 纸卡是桌面文档里的**开屏**（`#teSplash` 的 `.ts5-stage`，宽度 92vw）——它只有 1/4 屏，
   说明**装它的那个 iframe 只有大约 1/4 屏宽**。

### 已经试过的假设与结果

| 假设 | 做了什么 | 结果 |
| --- | --- | --- |
| WebView 的 `screen` 报物理像素（1080），被当平板放大 1.9 倍 | 8.08 改成以 CSS 视口判定 | 修好了"放大 1.9 倍"，但用户看到的变成了"缩小"，问题没消 |
| 首屏量尺寸时视口未稳，盒子被写成小值；而 `layout()` 被"开屏冻结"挡住、7.95 的自检也修不动 | 8.10 加 `layout(force)` + 冻结上限 2.5s + 自检用 force | 无头实测：冻结中把盒子改成 120×300，900ms 内自动回 393×838；**但用户实测"依旧"** |
| 页面是"半截加载"（17MB + iframe，5G 慢） | 用 Pages 版在无头里抓 1.5s/3s/6s/10s 四帧 | 无头里 1.5s 就是满屏纸卡，6s 进桌面；**没复现"小卡片"** |

### 还差一条数据（下一位最容易拿到的东西）

在出问题的那个环境里，打开 **设置 → 诊断 → 环境自检**（8.09 加的，不需要 URL 参数），
截图发出来。里面每一行对应的含义：

| 字段 | 正常值（手机） | 说明 |
| --- | --- | --- |
| `innerWidth × innerHeight` | ~393 × ~838 | 是 **1080** 左右 → WebView 没按 dpr 换算，视口被当成大屏 |
| `devicePixelRatio` | 2.5~3.5 | 是 **1** → WebView 没给 dpr |
| `visualViewport` | `393 × 838 scale 1.000` | `scale ≠ 1` → 页面被缩放（缩放链出问题） |
| `screen` | 与 innerWidth 同一量级 | 明显更大（1080×2412）→ 就是 WebView 的物理像素 |
| `meta viewport` | `width=device-width,initial-scale=1…` | 变成 `width=568,initial-scale=1.9` → tbFit 插手了 |
| `html zoom` | `1` | `1.9` 之类 → tbFit 的平板缩放生效 |
| `#jh-home 矩形` | `0, 0, 393, 838` | 宽高明显小于视口 → **就是盒子被量小了** |
| `桌面 iframe 视口` | 与 `innerWidth` 同量级 | 远小于 → 盒子锁死；远大于 → 缩放链 s 不对 |
| `桌面 data-mh/view/fit` | `phone / phone / 0` | 出现 `tablet` 或 `fit=1` → 桌面进了 1180×760 平板画布 |

### 拿不到截图时的兜底路线（建议直接做，别等）

**把桌面盒子从"JS 算尺寸 + transform 缩放"改成"CSS 直接铺满"**（我在 8.04 那轮想过没做）：

```css
html.jh-plain #jh-home{ left:0!important; top:0!important; right:0!important; bottom:0!important;
                        width:auto!important; height:auto!important; transform:none!important; }
```

`layout()` 里当 `s≈1 && fit≈1`（手机必然是）时给 `<html>` 挂 `jh-plain`，**不写** width/height/transform。
这样盒子永远等于视口，任何"量歪 / 冻结 / 缩放链"都可能失效 —— 代价是平板（s>1）那条老路要保留原逻辑。
改动点在 `_mobile/src/shell.html` 的 `layout()`（搜索 `box.dataset.tw=String(w)`）与 `#jh-home` 的 CSS，
建议做成 `round-812`，用 `?plain=0` 保留对照。
