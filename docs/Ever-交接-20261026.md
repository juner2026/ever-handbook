### 3.2 判案方法（下次直接照抄，别再猜）
**手机上装的 6.01 就是标准答案**，把它拉出来当基线做像素级对比：

```bash
adb-shell 'pm path com.tidalecho.app'      # → /data/app/.../base.apk，471MB，system:system 0644，shell 能读
# 本机已留一份解出来的 assets/index.html，别删：
ls -la /root/app601-assets-index.html      # 7,688,660 字节，__everVer="6.01"

# 同一个 headless 尺寸各渲一张，再 PIL 求差
/root/chrome-hs/chrome-linux/headless_shell --headless --no-sandbox --no-zygote \
  --disable-dev-shm-usage --disable-gpu --window-size=1238,826 --virtual-time-budget=10000 \
  --screenshot=/root/a.png 'http://127.0.0.1:8901/ever.html'
```

三件套一起用，5 分钟定位，比问用户十次都快：
1. 差异像素占比（`np.abs(a-b)>24`）；
2. 差异落在哪些网格块（`(x,y)` 分块计数）；
3. 注入 `getBoundingClientRect` 探针，沿**同一条祖先链**逐层比对（能立刻区分"布局位移"还是"transform/滚动位移"）。

### 3.5 ⚠️ 用户是用 `file:///` 打开的（这是"改了还是旧的"的另一半原因）

## 5. 打包链路（**全是坑，照这个来**）

### 5.1 `bash _apk/repack-assets.sh 6.xx [基础APK]`
不编译，**拿上一版 APK 换几个文件再签**：
1. 读 **`TidalEcho-手帐桌面.html`**（不是 `ever.html`！）；
2. 只替换 `assets/index.html`、`assets/aset/starvalley/index.html`、`assets/aset/home4/editor.html`；
3. 其它素材全部沿用基础 APK —— **新素材默认进不了包**（脚本已加"追加新条目"逻辑）；
4. `versionName` 必须 **4 个字符**（二进制清单里定长替换），`versionCode` 自动 +1；
5. 输出：`_发布/Ever-<ver>-<ts>.apk`，签名 `te-2026.keystore`；
6. 中间产物写在 `/root/repack-<ts>/`（**每个 905 MB，跑完请删**，这次一次清掉 14 GB）。

### 5.2 改内嵌桌面（`__JH_DOC`）
它是**转义后的 JS 字符串**：换行是字面量 `\n`、`<`/`>` 是 `\u003c`/`\u003e`、中文是 `\uXXXX`。
直接在源码里 `replace` 必须**用转义后的锚点**，否则 100% 找不到（我踩过）。可用 `python` 先 `eval` 出来改，再按原格式转义写回。

### 5.2b 只有装机包才有的路径（踩过一次：星露谷）
打包脚本会把源码里的本地目录名改写成包内路径（`家园素材/`→`aset/home/`、`ai-chat-paper-assets/`→`aset/paper/`、`日记本素材/`→`aset/diary/`、**6.32 起** `星露谷/index.html`→`aset/starvalley/index.html`）。
**源码里必须写本地目录名**，否则浏览器 / `file://` 拿不到。
反面教材：源码曾直接写 `aset/starvalley/index.html`，而本地 `aset/starvalley/` 是 **10-24 06:35 的旧快照**（354 KB / 69 文件），现行 `星露谷/` 是 **421 KB / 347 文件** —— 于是网页里星露谷=旧代码+找不到图，用户说“HTML 缺功能”。容器里 `aset/starvalley/` 现在无人引用，可留可删，**别再往里同步**。

### 5.3 装到手机
新版签名与 6.01 不同 → **必须卸载重装，6.01 的数据会一起没**。
`bmgr`（ADB 本地备份）被设备策略挡死（`[POLICY_BLOCKED]`，未识别命令）；root 无解（vivo 无官方解锁）。
→ **所以这条线目前是"只出包、不装机"**，用户已明确改为「**以后用 vivo 浏览器打开**」，别再自作主张打包装机。

## 12. 聊天分段器（segSplitText / _segShouldCut）

分段发送（设置里「AI消息分段发送」，`csToggle('segments')`）有**两个实现**，改一个必须改另一个，
否则"实时吐出来的切法"和"重进会话重绘的切法"会不一致：

| 函数 | 位置 | 用途 |
|---|---|---|
| `segSplitText` | 外层 ~18100 | 历史重绘 / 重新生成时切气泡 |
| `_segShouldCut` | 外层 ~17960 | 流式输出时判断"当前这段该收了没" |

**切点规则（6.33 之后）**：句子收尾（`。！？…!?`）、`；` 且够 80 字、空行且**上句已收尾**、
实在太长（260 字，且不切在逗号/括号前）。保护整体不被切开的有：代码块、`@@RD…@@` 卡片、
`<tool_x>…</tool_x>`、`@@STK:名字@@`、`[[…]]`、`【…】`。

**踩过的坑（6.33）**：空行原本一律算段界，于是 AI 只要在句子中间空一行，就会出现
"…虽然常常不那么完美了 / 但它是真实且可以切实依靠的。"这种半句话单独成气泡。
现在空行要上句已收尾才切。
另外别想着"末段太短就并回上一段"——试过，会把正常的短段落（"对了，晚饭记得吃好一点。"、"好。"）一起吞掉，已撤。

自测方法（不用开界面）：把 `segSplitText` 和 `splitSegments` 两段源码抽到 `/tmp/t.js`，
末尾加 `console.log(segSplitText(process.argv[2]))`，然后 `node /tmp/t.js` 传一段文本进去即可。

## 15. `data-fit="1"`（平板预览）下的比例

**触发条件**：内层视口宽度 < 1024 时，桌面进 fit 模式 —— 把 1180×760 的平板布局整体
`translate(-50%,-50%) rotate(var(--rot)) scale(var(--fit))` 塞进屏幕。竖屏时 `--rot=90`，转 90° 才读得清。

**踩过的两个坑（6.39 已修）**：

1. `html.scrapbook .app` / `html.editorial .app` 里的 `transform:none!important`
   会把 fit 的 `translate(-50%,-50%)` 一起吃没，只剩 `fixed; left:50%; top:50%`
   → 整本手帐钉在屏幕右下、右/下全裁。**两套皮肤都中招**。→ 两条规则加 `:not([data-fit="1"])`。
2. 竖屏的 `rotate` 原来写成独立 CSS 属性，和 `translate(-50%,-50%)` 组合时居中失效
   → 转到屏幕外（空白）。→ 改成 `transform:translate(-50%,-50%) rotate(...) scale(...)`，`rotate:none`。

**验证方式**：`--window-size=825,525` / `525,825` 各渲一张对比；
`1239×827` 那张**字节数必须和改前完全一致**（1281031），用来证明没有回归。

### 现在的唯一入口

```js

```

- `srcClean`：只去掉可执行标签的版本，写进历史用它（保持旧行为，表情包 `@@STK:` 等标记不受影响）；
- `leftover`：转义了几处，调试用。

配套两件：

1. **执行台账** `_tcTakeNew('r'+_tcHash(fullText), calls)` —— 同一条回复里的同一个调用只跑一次。
   键 = `_tcKey()`（type|srv|tool|op|path|idx|slot|who|item|正文前160字），
   台账最多留 60 条回复的指纹，别的地方重试 / 重复 finish 不再双跑同一个动作。
2. **统一执行 `_tcRun(call, fn)`** —— 每支一张收据 `{ok, msg}`；抛异常不再无声无息，
   走 `console.warn` + `mdbg`。顺带一个行为改进：**某一支炸了不再中断后面几支**。

另外修了一个参数丢失：`_mcpSplitParts` 里 `JSON.parse` 失败时 AI 的多行 JSON 参数全丢，

## 17. MCP 结构化 + 时间感知复位（6.60）

### 17.1 MCP 走同一套工具层（照 Operit 的工具循环）

以前 MCP 是一条独立的链（`mcpExtract` → `mcpCall` → 手写回执），和 6.59 那套统一层并行，
问题正好是 Operit 专门解决的几件事：

| 病 | 以前 | 现在 |
|---|---|---|
| 成败靠猜 | `mcpCall` 只 res 一段中文；调用方 `String(r).indexOf('失败')<0` 判断成败 | `mcpCall2` 统一返回 `{ok, text, err, code, ms}`，`code` = `ok / no_server / timeout / rpc_error / call_error / exception` |
| 没有超时 | 指望底层 fetch 自己 reject | 自己兜 45 秒（`MCP_TIMEOUT`），超时也返回结构化结果 |
| 重复执行 | 内存 `_mcpDoneKey` + `last._mcpDone` 标记 | 再叠一层执行台账 `_tcTakeNew('mcp'+_tcHash(content), calls)` |
| 闸门散落 | 服务器开关一个 if、白名单另一个 if，还各自 `return` | `_mcpGate(c)` 一处返回 `{ok, code, msg}`，拦下时把**原因**写在旁白里 |
| 抽取口径不同 | `mcpExtract` 自己一套正则 | 走 `parseToolCalls().calls`，标签 / 裸行 / JSON 信封三种写法一致 |

**Operit 同款 JSON 信封**（新增，可选）：

```
{"tool":"服务器|工具","args":{"参数":"值"}}          ← 一行
{"server":"服务器","tool":"工具","args":{}}          ← 也可以
```

`_parseToolCalls` 认它，`_stripToolTags` 会把这一行从正文里删掉（**只认整行、且以 tool/server/srv 开头**，
普通 JSON 不动 —— 有测试 ⑩ 守着）。MCP 工具清单里那段「调用格式」已经两种写法都写上了。

### 17.2 时间感知 / 深度时间感知 —— 「贴他脑门上了」

用户原话：「我开的那个时间感知和深度时间感知之后，AI 一直在说时间和我上一条消息和这条消息隔了多久。
问了他一下，他说这玩意儿贴他脑门上了」。

病根就在这里（`callChatAPI`）：

```js
userContent='【当前时间】…\n'+userText;
if(csBool('timegap',true)) userContent='【时间】'+_gap+'\n'+userContent;
```

- 前缀**直接粘在她的消息头上**，模型当成她这句话的一部分；
- `_timeGapText()` 的原文还写着「她要是问时间，就用这个数答，别猜」——等于每轮把秒表怼到它脸上；
- 而且 `timegap` **默认是开**的（`CS_DEF.timegap:1`）。

现在：

1. 前缀整段删掉，改成一条**独立环境块**，塞进可变尾巴（`window._sysVol`），
   排在她说的话**后面**，标题就是「【环境 · 不是她的话】」；
2. 块尾硬规则：「**不要**主动说『你上一条和这条隔了多久』这类话；只有她问到时间、
   或者话题本身和"过了多久"有关时才用；也不要复述这一节。」
3. `_timeGapText()` 只输出事实：`距上一条消息：3 小时 20 分钟（她上一条消息）`，
   删掉所有指令句；**十分钟以内直接不输出**（「隔了 43 秒 / 2 分钟」纯噪音）；
4. `CS_DEF.timegap` 默认 `1 → 0`；
5. 群聊那条同款措辞一起改了（`【环境 · 不是谁的话】群里距上一条消息 …`）；
6. 设置页说明改成「让它知道隔了多久（只作背景，除非你问，否则不会主动提）」。

- 解析层：`node /tmp/tctest.js` → **23/23**（新增 ⑧ 信封、⑨ server/tool 分开写、⑩ 普通 JSON 不动）

## 18. 中断恢复（6.61 · Operit 工具循环第 3 条）

### 18.1 病：按了「停止」，屏幕上的话算数，背后的动作不算数

流式回复里有 `<tool_…>`，她在写到一半时点停止 → `finish()` 不跑 → **那些调用一个都不执行**，
而且这条半截回复**不进历史**。于是：

- 屏幕上她看见「我记下来了 / 发出去了」；
- 记忆库、动态、MCP 一样没动；
- 下一轮 AI 自己也不知道没发生（历史里没有这条），可能继续说「刚才已经寄了」。

这正是 Operit 的 interrupt recovery 要治的东西：**中断必须留下一份诚实的回执**。

### 18.2 做法：`_tcInterruptSweep()`（挂在 `stopChatReply()` 最前面）

1. 从**流式草稿**里捞那段半截正文（`_draftSave` 一直在往 `localStorage['chat_draft']` 写，
   600ms 一次，正好够用）；
2. `parseToolCalls()` 解析出调用（没有调用就只清草稿，不写任何东西）；
3. 写一条回执进历史（`role:'user', _silent:1, _tcAbort:1`）：
   「【工具回执 · 被打断】…这些动作**没有执行**…你正文里如果说"已经做了"，那件事其实没发生」；
4. **台账占坑两个命名空间**（`'r'+hash` 和 `'mcp'+hash`）—— 她点停止就是不想跑，
   之后不管哪条路径重新解析到这段文本，都不许"补跑"；
5. 屏幕留一句旁白：「（已中断：这轮写下的 N 个动作没有执行）」。

### 18.3 MCP 能连续调用吗（回答用户提问）

**能，两层，都受上限管：**

| 层 | 机制 | 上限 |
|---|---|---|
| 同一条回复里 | 写多个 `<tool_mcp>`，会**并发**发出（`calls.forEach` → `_jobs` → `Promise.all`） | 不设条数上限，但每条结果都进历史，太长的上下文自己会撑 |
| 跨轮自动续跑 | 结果回执落盘后 `dvTriggerReply()` 自动再问一次模型 | `localStorage['te_mcp_chain']`，默认 **4**，夹在 **1~12**；如果这条回复除标签外**没有正文**（纯干活，`_proseOnly`），放宽到 `max(上限, 8)` |
| 结果长度 | `mcpTrimForAI` | 默认**不截断**（`te_mcp_cap` 未设置 = 0）；硬天花板 `MCP_HARD_CAP = 200000` 字，真砍了会明确告知并给续取参数 |
| 闸门 | `_mcpGate`：总闸 / 服务器开关 / 工具白名单，**每次调用都过** | — |

撞到上限时屏幕上会有一行：「已连续执行 N 次工具调用，达到上限（M）—— 你说句话我就接着走」。
想放宽：`te_mcp_chain` 改成 8 或 12（目前没有界面，只有这个键）。

### 18.4 验证

`node /tmp/aborttest.js` → **11/11**：
① 半截正文里 2 个调用（memorize + mcp）→ 全认出来、草稿清掉、历史回执、旁白、文案含"没有执行"；
② 台账两个命名空间都占坑（实时路径 2/2、MCP 路径 1/1 全跳过）；
③ 只有正文没有调用 → 不写回执、草稿照样清；④ 没有草稿 → 安静返回。

回归：`tctest 23/23`、`mcptest 13/13`、`chk.py 69 blocks / 66 ok`、

## 19. 连续回复把她的消息重答一遍（6.62）

### 19.1 病

截图里连着好几条 AI 消息，内容几乎是同一句话的不同写法（「骂谁臭呢，小猫？」/「嘴上硬得很，有本事你饭也别吃」/
「五点零四分了…」），而且每轮都重新回答她那条「臭老公」。

### 19.2 根因：续跑把她的话当成新消息重发了一遍

```js
function dvTriggerReply(){          /* 工具回执 / 占卜 / 工作流回报之后都由它续跑 */
  var lastU = ...最后一个 user 的 content...;
  callChatAPI(lastU, holder, tpId);   /* ← 原样当作"她刚说的话"再发一次 */
}
```

而 `callChatAPI` 里有两步配合，把这件事变成灾难：

1. `hist` 里**无条件删掉最后一条 user**（注释写着"当前 user 已经写入历史，必须去掉它"）——
   续跑时根本没有新消息写入，于是被删掉的其实是**上一条工具回执**；
2. 结尾 `.concat([{role:'user',content:_ucFinal}])` 把她的原话当**最新一条**发出去。

在模型看来就是：工具回执不见了、她又说了一遍「臭老公」→ 只能重新回答一遍。
每续跑一次，就多一段几乎一样的回复。

### 19.3 做法：给 `callChatAPI` 加第 5 个参数 `_cont`

| 环节 | 改动 |
|---|---|
| 签名 | `callChatAPI(userText,holderId,tpId,_try,_cont)`，内部 `_contMode=!!_cont` |
| 历史 | `_contMode` 时**一个字都不动**（不删最后一条 user） |
| 最后一条 | 不再发她的原话，改发「（系统：接着上一条继续往下说。不要重复你刚才说过的内容，也不要重新回答她上一条消息。）」 |
| 相邻 user | 若历史最后一条本身就是 user（工具回执），把这句提示**并进去**、不再多一条 —— 避免连续两条 user（有的服务会 422） |
| 写历史 | `finish()` 与 `_liveHistFlush()` 在续跑时**不**补写 user（否则历史里会攒一堆"接着写"） |
| 重试 | `callChatAPI(...,_try+1,_contMode)` 把标记带上，重试不会退回旧行为 |
| 入口 | `dvTriggerReply()` → `callChatAPI('', holder, tpId, 0, true)` |

爱心那条路（点♥让它接着说）**没改**：那是她主动要再说一句，`_ut` 后面本来就缀了
「这句话你已经回过了…」的提示，属于另一个语义。

### 19.4 验证（真跑，不是看代码）

用一个 iframe 把 `ever.html` 真加载起来，替换掉 `window.fetch` 截获请求体，再调 `dvTriggerReply()`：

```
history 预置：臭老公 / 骂谁臭呢，小猫？ / 【MCP 工具回执】x → y
实际发出的 messages：total=4
  0 user      臭老公
  1 assistant 骂谁臭呢，小猫？
  2 user      【MCP 工具回执…】x → y + （系统：接着上一条继续往下说…）
herCount = 1        ← 她的原话只出现一次，且在开头当上下文
lastRole = user     ← 最后一条是"接着写"的提示（并进了回执），不是她的原话
```

改前同样的探针会显示最后一条 user 就是「臭老公」（等于她把话又说了一遍）。
