## 这一版只改一件事：点全屏不再黑一段时间

**根因**：进/退全屏只改「含不含状态栏、地址栏」的视口高度（几十像素），
但它会触发 `relayout()` → `layout()`，把那本 4.2MB 的内联桌面 iframe **按新尺寸重排一次**。
重排期间那一层画不出来 —— 就是用户看到的「黑一段时间」。

**改法（`round-7.84`）**：

1. `fullscreenchange` 一响，记 `window.__teFsSwapUntil = now + 3000`
2. 3 秒内 `layout()` **自己**直接让路（在函数第一行），所有调用方一起挡住；
   `relayout()` / `check()` 也各加一道闸
3. 让路期间不重排，改成 `__teFsFit()`：**沿用旧盒子尺寸，只改外层 `transform: scale(k)`**
   铺满新视口 —— 只走合成层，桌面文档一个字都不用重排
4. `check()` 在让路期间照常更新尺寸基线，避免 3 秒后又补一次重排

实测（headless，模拟 `932 → 1022` 的高度变化）：

| | 盒子高 | 结果 |
| --- | --- | --- |
| 改前 | 被改成 1022 → iframe 重排 | 一整层重画（真机上就是黑那一段） |
| 改后 | **保持 932**，`transform: scale(...)` + 居中 | 零重排 |

代价：视口只高不宽时（手机竖屏去掉地址栏），等比铺满受**宽度**限制，上下会各留一条
页面底色的纸边（不是黑色，是 App 自己的米色底）。如果更在意"完全铺满"，可以反过来选
"重排 + 一张米色遮罩顶住那一瞬"——说一声我换。
