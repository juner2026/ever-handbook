## 二、家园聊天窗拖不动 —— 宿主转 90° 后坐标被夹错

`#teHome4` 在竖着拿手机时是 `rotate(90deg)`，聊天窗是它的子节点，`HQ.off` 存的是**宿主局部坐标**。
`hqClampPos()` 却拿 `getBoundingClientRect()`（**屏幕坐标**）去夹这个局部偏移：
转了 90° 之后屏幕 x 和局部 y 混在一起 → 可动范围算错。

改法：先在屏幕上算合法范围，再按 90° 换算回局部坐标（屏幕 (sx,sy) ↔ 局部 (sy,−sx)）。

实测（同一组拖动，7.94 → 7.95）：

| 拖动 | 7.94（改前） | 7.95（改后） |
| --- | --- | --- |
| (−150,−120) | 屏幕只挪了 (−6,−12)，像"拖不动" | (−12,−120)，还差一点到左边界（被正确夹住） |
| (+100,+150) | 挪到 y=714，**窗口底部跑到屏幕外**（714+330 > 932） | 挪到 y=596，底边 926，贴着安全边 |
| (−60,+40) | 横向几乎不动 | (−60,0)，正常 |

## 三、整页"弹到右下角"：先加自检纠偏

`#jh-home` 是 `position:fixed;inset:0` 的整屏盒子，正常情况下
`getBoundingClientRect()` 必须等于 `(0,0,innerWidth,innerHeight)`。
用户截图那个状态（整块缩小、偏到右下）说明某一刻 `layout()` 把
width/height/transform 写成了一组对不上的值（`fit` / `__teFreeze` 基准 / `appScale`
任意一个取到脏值都会这样），而且会一直停在那儿。

**先说清楚：这一版没有找到"谁写脏了"，而是加了一张网**：

- 每 250ms、resize、点按后各查一次盒子矩形；
- 偏离视口 >3px（或 `scale`/`fit` 明显异常）→ 把冻结基准复位成当前视口、
  清掉 `layout()` 的签名缓存、重排一次；连续修 3 次还不对就按视口硬钉一次；
- 同时把现场写进 `localStorage['te_bad_layout']`（矩形、内联样式、tw/th/scale/fit、freeze 基准），
  下次复现可以直接读出来定位真凶。

实测：人为把盒子弄成用户截图那个状态 `(215,470,860,1864)`，**900ms 内自动回到 `(0,0,430,932)`**，
诊断记录也写下了。

## 六、待用户指认：群聊"显示的是单聊界面"

用户说「现在这版的群聊显示的是单聊界面」。查过的事实：

- 全库里群聊**只有一套**实现：`gcOpen()` 动态建的 `#gcOv`（`.gcwrap`）；

  和首页那张 `onclick="gcOpen()"` 的卡，都会建出 `#gcOv`（class 变 `gcwrap on`，标题「群聊」）；
- `gcMsgsHtml()` 渲染正常：AI 气泡带「头像 + 名字」，用户气泡是「你」，时间正常，
  HTML 里没有 NaN。

所以要么用户手机上还是旧的一份（缓存/PWA），要么他说的"群聊"是另一个入口。
