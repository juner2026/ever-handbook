## 5. 桌面"锁死不转"（用户选定方案 3）—— **已做完，见 `Ever-7.34-锁死不转.md`**

> 下面是当时的方案记录，留档用；实际实现：第一次点按静默进全屏 + `orientation.lock('portrait')`，
> 锁不住就冻结竖屏尺寸、整块等比缩小（不重排）。`?nolock=1` 可关。

**目标**：手机转动时，页面版式**保持不变**（不重排、不缩放、不跟着转）。

推荐实现（按优先级）：

1. **Fullscreen + 方向锁**（最接近"App 锁竖屏"）
   - 在**任意一次用户点击的同一手势内**调用：
     ```js
     el.requestFullscreen().then(()=> screen.orientation.lock('portrait')).catch(()=>{});
     ```
   - 注意：`requestFullscreen()` 必须由用户手势触发；`lock()` 必须页面已全屏，否则必然失败（这一条踩过很多次）
   - 在 Edge/Chromium 上这条成功率最高；vivo 浏览器不支持（所以必须用 Edge）

2. **纯 JS 冻结布局**（锁不了方向时的兜底）
   - 首次加载记录 `W0,H0`（竖屏尺寸），之后忽略 `resize`/`orientationchange` 引起的**尺寸变化**：照旧用 `W0,H0` 计算缩放与 `.screen` 宽度。
   - 只对 `#jh-home`（手帐本体）生效，不影响游戏层。

3. **不要**再用 CSS `rotate` 去模拟竖屏（今天证明：会让 fixed 元素错位、按钮变竖、iframe 拿到错尺寸）。

验收标准：手机横过来 → 手帐版式**一模一样**，不重排、不缩放、内容不移动。

## 7. 工具与调试（本轮学到的，能省很多时间）

- **截屏现在可用**：MCP `android_screenshot`。若返回 `Maximum call stack size exceeded`，直接读
  `/sdcard/Android/data/com.dsh.client/files/Pictures/DSHA/*.png`，用 PIL 缩小后再看：
  ```python
  from PIL import Image
  im=Image.open(path); im.thumbnail((900,1350)); im.convert('RGB').save('/root/shot.jpg', quality=80)
  ```
- ⚠️ **PIL 要在 `/root` 下跑**：`/tmp/bisect.py` 会遮蔽标准库，导致 `random` 导入失败。
- **探针模式（页面里取证）**：同源最稳的是 appending `<script>` 到页面副本，然后 `<img src="/ping?d=...">` 把 JSON 打回 8903（`/root/fontsrv.py` 会把 `/ping` 写进 `/tmp/ping.log`）。**16MB 页面里的 fetch 探针会被吞，img ping 更可靠。**
- 探针**不要 gate 在 `__jhSplashDone`** 上（开屏约 9 秒，容易等不到）。
- `/app/open` 用默认浏览器；`am start -p xxx` 被设备策略挡（`[POLICY_BLOCKED] 不认识的命令：am`），**没法指定浏览器**。
- 设备上只有两个浏览器：`com.vivo.browser`（会闪退）、`com.android.browser`；用户后来装了 **Edge**。
