## 一、这一版做了什么

### ① 家园强制横屏，这次是"不弹"的版本

上一轮（7.85~7.87）失败的原因是**顺序**，不是"旋转"这件事本身。这次按两条实测出来的
规律重做：

1. **先量后显示**：`build()` 里盒子一建出来（还没进 DOM）就按横屏算好宽高，
   `teHomeEnter` 里再 `__m2HomeFit(box)` 一次，最后才 `display:block`。
   这样家园 iframe 的**第一次**布局就是 `932×430`。
   以前是"先进家园（竖屏 430×932）→ 再转 90°"，编辑器 `resize()` 把整间屋子重新缩放一遍，
   就是用户说的"画面跳一下"。
2. **尺寸只在真的变了才重算**：`__m2HomeFit` 用 `__fitCls/__fitW/__fitH` 记住上次的尺寸，
   相同就一个样式都不写；**打字中**（焦点在输入框，或焦点在家园 iframe 里且里面是输入框）
   一律不动 —— 软键盘只改 `innerHeight`，不能让家园每打一个字重排一次。
3. 手机**物理转成横屏**时：视口本身变成 `932×430`，跟旋转后的 iframe 视口**一模一样**，
   所以 `canvas` 一次都不重排（实测 `cv` 前后完全一致）。转回竖屏也一样。

只动 `#teHome4` 这一层：不碰 `requestFullscreen`、不动手帐桌面、不动 App 其它页面。
小窗拖动沿用 7.81 的 `hqHostFrame().rot`（宿主转 90° 时把屏幕位移换算回宿主坐标），实测拖动正常。

### ② 退出家园时"整页空白一下再弹回来" —— 真凶找到了

`html:not(.jh-home-on) #jh-home{display:none!important}` + `syncHomeClass()` 800ms 一次的轮询：

- 进家园约 800ms 后 `jh-home-on` 被摘掉 → 整本 13 万行桌面 `display:none`；
- 退出家园时 `teHomeLeave` 又**先把所有 `.pg` 的 on 全摘掉再加回来**，
  中间有一瞬"没有任何页面是 on"，而且 `jh-home-on` 要等下一轮 800ms 轮询才恢复；
- 实测：退出后 **0~500ms 是空白帧**（430×932 的截图只有 12KB），然后整块桌面才拍上来。

改法：

| 改动 | 说明 |
| --- | --- |
| `display:none` → `visibility:hidden` | 布局一直留着，回来只重画，不重排 |
| 新增 `html.te-home-open #jh-home{display:block;visibility:visible;pointer-events:none}` | 家园开着时桌面继续挂着画（家园那层不透明），退出零重排 |
| `teHomeLeave` 先加回上一页、立刻 `jh-home-on` 摆正 | 不再等 800ms 轮询；`te-home-open` 最后才摘 |
| `syncHomeClass()` 里顺手 `__teHomeHold(!on)` | 不在首页时暂停桌面文档里的 `@keyframes`（`animation-play-state:paused`，**不是** `animation:none` —— 那样会从第 0 帧重播，7.87 踩过），回首页原地恢复 |
| `#jh-home` 加 `will-change:transform` | 见第三节 |

### ③ 家园横过来后，全屏珍珠把「返回」挡住了

家园转 90° 之后，编辑器自己那个「返回」正好落在**屏幕右上角** —— 也就是全屏珍珠
（`#everFsPearl`，`z-index:2147483002`）的位置。实测点下去只会触发全屏（还会空白一阵），
根本退不出家园。现在家园期间先把珍珠收起来：

```css
html.te-home-open #everFsPearl{display:none!important}
```

实测：家园里右上角点到的是 `teH4frame`（不再是珍珠），在家园里点它自己的「返回」
能正常回到桌面、珍珠自动回来。

### ④ 顺手：桌面层固定成常驻合成层

`#jh-home` 靠 `transform:scale(1/s)` 缩放，合成器每次重排/重画都要按新比例重新栅格化。
headless 里在**页面切换的那 1~2 帧**能稳定复现一种错帧：桌面被按旧比例（2×）1:1 贴上来，
看起来就是"整页忽然放大、偏到右下角"。几何一次都没变（逐帧量过 rect / `--z` / `.page` 的 transform），
纯栅格问题。加 `will-change:transform` 后同一组采样里错帧 2 → 0（`_mobile/shots/ab-*`）。
**这条只在无头里验证过，真机还需要用户确认。**

## 三、这一版**没有**做的

1. **全屏珍珠黑一阵**：7.91 的米色遮罩还在。如果用户还看到黑，说明是 WebView 自己重建系统窗口，
   HTML 遮罩盖不住 —— 下一步只能不调 `requestFullscreen`，改 App 内沉浸模式。
2. **AI 工具调用没显示在思考链 / 用户气泡不是透明 / 设置页顶栏不是磨砂**：本轮没碰。
3. **"每点一下都弹动"**：无头里只复现出"页面切换后 1~2 帧错比例栅格"，点按本身量不到任何几何变化。
   如果真机上还在，需要用户给一个具体动作（点哪里、第几次）或录屏。
