## 4. 关键实现点（别踩这些坑）

1. **同一份文档手机平板共用**：新样式必须写在 `m2-apps.css` 且以 `html[data-mh="phone"]` 开头，否则平板跟着变（用户明令不动平板）。
2. **文档自带一堆 `!important`**，覆盖要拼特异性：
   - `.slot.jh-natural-photo .ph[data-full="1"]{overflow:visible!important}` → 反向要写 `html[data-mh="phone"] .slot.jh-natural-photo .ph[data-full="1"]{overflow:hidden!important}`
   - `object-fit:cover!important` 有两处：`.slot[data-slot]` 与 `.slot--special.jh-natural-photo`
3. **`.ph` 里绝对不要写 `height:100%`**：会把 `.sb-album` 撑到几千万像素，P1 下面全空（已踩过一次，回滚解决）。
4. **文档的点击拦截在 capture 阶段**：任何 `[data-open]` 元素的点击先被它吃掉。要自己处理点击就别让元素带 `data-open`（表情包卡是直接改 `jh-doc.html` 把属性拿掉）。
5. **树上吊牌原来是裸 key**（`star/home/map…`），外壳只认 `app:xxx`：已用 `treeLinks()` 补齐，并额外挂 `parent.nav(page)` 直连兜底。
6. **换图**统一 `<label for>` + 透明 `<input class="m2img-inp">` 覆盖整块（`pointer-events:auto;z-index:6`），存 `te2_m2img_*`；照片槽存 `te2_ph_*`。
7. **体积**：`aset/` 被引用的图都会 base64 内联；千万别把 base64 写回源码（曾把源文件撑到 891KB）。
8. **<10px 的小注不吃主题字体**：装饰字体在 8~9px 会糊，`m2-apps.css` 末尾有一段
   `m2sysfont-small`（42 条选择器）把它们钉回无衬线。**别手改那一段** ——
   改了字号/新增小字规则后跑 `python3 _mobile/tools/gen-small-font.py` 重新生成。
9. **"一滑动就被打回顶部"（2026-10-31 修）**：实测把 `#sc1.scrollTop` 设成 800、全程无手势，
   0.7 秒后自己变 0，而 `scrollHeight/clientHeight` 不变，也没有任何 JS 去写
   `scrollTop / scrollTo / scrollIntoView` —— 是页面里那套周期性重排把滚动容器重置的。
   已做三件事：① `fitWide()` 里 `--te-k`、`computeZoom()` 里 `--z` 改成「值没变就不写」；
   ② `m2-apps.js` 加 `scrollKeeper()`：认出「一帧掉 150px 以上且落回顶部附近、手指不在屏上」
   就立刻还原位置（正常拖动/惯性每帧只有几十像素，不会误判）。
   **别把 scrollKeeper 删掉** —— 底层那套重排还没根除，它是兜底。
10. **翻页胶囊 / 回原屏（2026-10-31 修）**：手机布局下点圆点、调 `__m2GoScreen(1)(2)`，
    `track.scrollLeft` 一直是 0 —— 原版给圆点绑的 click 在手机版里没生效。
    连带后果：`te2_scr` 永远存 0，于是"点开应用再返回"总落到第 1 屏，手动翻也翻不动。
    现在 `m2-apps.js` 的 `pager()` 不再依赖圆点自身 click：直接滚 `.track`（auto 定位 + 320ms 后补一次，
    防 snap 抢回），并用 document 上的 capture 委托接圆点点击与 track 滚动，同步圆点 `on` 与 `te2_scr`。
    实测 0→1→2→0→1 全部正确，圆点、位置、存档三者同步。
11. **"点应用 → 返回"回到第 1 屏（2026-10-31 修）**：两处都会把 `te2_scr` 冲成 0 ——
    ① `trackScreen()` 启动时 `save()` 一次（当时 track 还在第 1 屏）；
    ② 圆点 class 的 MutationObserver 也会在启动时存一次。
    现在 `trackScreen()` 只负责挂 `__m2GoScreen`，**存档只由 `pager()` 在真的翻页/滚动时写**；
    `pagerPaint(..., save=false)` 用于启动时的"只画圆点不存档"。
    实测：`te2_scr=1` → 开星海 → 返回 → `dotOn=1 / scrollLeft=1178 / te2_scr=1`，回到第 2 屏。
12. **点树上的吊牌/应用"没反应"、"点一下像退出了"（2026-10-31 修）**：两个原因
    ① `jh:nav` 在开屏没播完时**直接 return 丢弃**（`__jhSplashDone` 要到 9 秒左右才置 1），
       用户在开屏后那几秒点吊牌/应用卡，点多少次都没反应 → 改成**排队**，开屏结束 `__jhFlushNav()` 补执行；
    ② `nav(p)` 遇到没有对应页面的 key（树上的 Roster 就没有 `p-roster`）时，先把所有 `.pg` 的 on 摘掉、
       再加不上新的 → 整页空白，看着像"退出了" → 现在找不到页面就回首页。
    实测：开屏中(2.5s)点星海 → 14.5s 开屏结束自动跳 p-star；`nav('roster')` → 落在 p-home 且页面不空。
13. **字体改成宋体（2026-10-31）**：用户要"华康宋体"（商业字体，拿不到），改用同气质的开源
    思源宋体 Noto Serif SC（SIL OFL）。做法：
    ① `fonttools` 已 `apt install python3-fonttools`（4.46.0），用
       `python3 -m fontTools.subset ... --text-file=charset.txt --flavor=woff2` 按页面实际用到的
       4129 个字符裁子集 → `aset/fonts/m2serif-400.woff2`(723KB) / `-600.woff2`(734KB)；
    ② `build.py` 的 `inline_assets` 扩展了 `FONT_EXT`，`aset/**/*.woff2` 会内联成 `data:font/woff2`；
    ③ `m2-apps.css` 加两个 `@font-face`（family `M2Serif`），`--cn: 'M2Serif', system-ui, …`。
    产物因此从 16.24MB 涨到 18.18MB。**改字重/换字体要重新跑子集化**，别直接换 woff2 路径。
    注：<10px 的小注仍被 `m2sysfont-small` 钉成无衬线（用户早前的要求），要统一成宋体就删那一段。
14. **"返回首页后要点好几次才进得去"（2026-10-31 修）**：`shell.html` 的 `guardHomeTouch()`
    原来是 `box.style.pointerEvents='none'` 封 **600ms**，而且 `window.nav` 每次 `p==='home'` 都会调它 ——
    返回后马上点树上吊牌，这 0.6 秒里点几次全被吃掉（本意是防"同一手势穿透打到卡片"）。
    现在改成：不封屏，只挂一次性捕获监听，**140ms 内最多吞掉一个 click**（shell 和 iframe 两边都挂），
    之后立刻解除；真正的新点击照常生效。
15. **"点得不一定"（2026-10-31，已加兜底但未定位根因）**：
    现象 = 同一个吊牌有时 1 下进、有时 2~4 下才进，不同应用都是，次数不固定。
    已排除：吊牌节点被替换（8 秒实测 0 次）、`nav()` 不执行（每次点击 nav 都被调用）。
    合成点击（`el.click()`）每次都成功 → 说明是**真实触摸**这一路被吞（手势判定/click 抑制），
    本机没法直接注入真实触摸，所以改为兜底：`m2-apps.js` 的 `tapRescue()` ——
    touchstart 记坐标，touchend 时若位移 ≤22px、时长 ≤800ms，就用 `elementFromPoint`
    重新命中 `[data-open="app:*"]`，若 300ms 内没有正常导航发生就自己补发 `jh:nav`。
    **若还复现**：把 22 调大 / 在 touchmove 里也记一次坐标；根因可能在首页横向 pan 的手势判定。
16. **日记/星露谷没有返回键、日记"合上"直接退出（2026-10-31 修）**：
    ① `aset/diary/book.html` 的 `closeBook()` 原来会 `post({t:'te:diary2:close'})`，
       父页面 `teDiaryClose()` = 隐藏覆盖层 + `nav('home')` → "合上"等于"退出日记"。
       已删掉那条 post（合上只回书架）；**注意 `#teDiaryFrame` 的 src 必须带版本号
       `?v=20261031-1`**，否则浏览器缓存里还是旧 book.html，改了也不生效（踩过）。
    ② 日记覆盖层新增 `#teDiaryBack`（左上「‹ 返回」胶囊，调 `teDiaryClose()`）。
    ③ 星露谷的 `#svClose` 原来**没有任何 CSS**，躺在文档流里被 99990 全屏层压住 → 看不见；
       已补成固定胶囊并把文字改成「‹ 返回」。
17. **日记页打包进单文件（2026-10-31）**：`build.py` 新增 `INLINE_PAGES = ['aset/diary/book.html']`，
    构建时把子页面内部的图片换成 data URI、整页 base64 后写入 `window.__M2_INLINE`，
    iframe 用 `window.__m2Src(url)` 取（没打包过的原样返回）。
    产物 18.19MB → 19.38MB（日记页 data URI 1162KB，解出 889KB 源码，两张封面已内联）。
    **星露谷（整目录 434MB）和家园（14MB）塞不进来**，仍然是外部依赖；
    只拷 ever.html 时它们会是白屏 —— 要彻底解决得改成 zip/离线包，成本另算。
18. **星露谷/家园：强制横屏 + 返回键（2026-10-31）**
    · `manifest.webmanifest` 恢复 `"orientation": "portrait"`（桌面锁竖屏；
      装成 PWA 时要删图标重加才生效）；
    · 新增 `window.__m2ForceLandscape(el)`：视口是竖的就把元素 `rotate(90deg)` 并
      宽高互换铺满，横的直接铺满。星露谷（`#svTopWrap`）和家园（`#teHome4`）都用它；
    · 星露谷的覆盖层从"文档层"挪到**外壳层** `#svTopWrap`（文档被 `.app` 的
      `transform:scale(--z)` 缩放过，fixed 在里层会算错尺寸）；
    · iframe 必须"先 display:block、下一帧再设 src"，否则隐藏状态下初始化成 0×0；
    · **返回按钮一定要挂在 body 上**，不能放进被 rotate 的 wrap 里 ——
      里面的 `position:fixed` 会跟着转，跑出屏幕（用户："返回点半天才退出去"）；
    · 星海返回"闪一下"：`nav('home')` 里恢复原屏的定时器加了 0ms 那一档，
      同一帧就把轨道摆到目标屏，不再先露第 1 屏再跳。
19. **浏览器 / 体积 / 竖屏（2026-10-31 后半段，务必先读）**
    · **vivo 浏览器吞不下 16MB+ 单文件，打开就闪退**；20MB 级更不行。
      用户装了 **Edge（com.microsoft.emmx）**，同一个页面在 Edge 里正常。
      以后验证请用 Edge（或让用户把 Edge 设为默认浏览器）。
