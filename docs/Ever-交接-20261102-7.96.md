用户原话：「树上提示的群聊是单聊界面」。**这条是真的，根因在 m2 补丁里。**

---

## 一、根因

`_mobile/src/patch/m2-apps.js` 第 21 节（手帐桌面那棵树上的 7 枚吊牌）：

```js
var TREE_OPEN = {
  star:'app:star', home:'app:home', map:'app:map', diary:'app:diary',
  roster:'app:roster', group:'app:chat', stk:'app:stk', stickers:'app:stk',
  ...
};
```

原始 key 是裸的（`group`），m2 补丁给它们补 `app:` 前缀时**把 group 写成了 `app:chat`** ——
于是树上那枚「群聊」吊牌打开的是**单聊页**。

同一段下面还有一条"直连兜底"：`parent.nav(page)` —— `nav()` 只认页面 id（`p-chat` 这种），
`group` / `roster` / `stickers` 这些没有对应页面的 key 要么掉回首页，要么开错页。

## 二、改法

1. `group: 'app:group'`；
2. 吊牌点击不再硬编码 `parent.nav(page)`，改成调外壳新暴露的
   **`jhOpenKey(key)`** —— 让外壳用**同一张 MAP** 决定开哪儿：
   - `group` → `gcOpen()`（群聊层）
   - `roster` → `aiInfoOpen()`
   - `stickers/stk` → `stkOpen()`
   - `home` → `teHomeEnter()`（家园）
   - `star/map/diary` → 对应页面
3. `jh:nav` 的 MAP 查找补一条 `MAP[k]`（剥掉 `app:` 前缀后的 key），
   顺手把之前只认裸 key 的入口修好。

## 三、实测（桌面上那 7 枚吊牌逐个点）

```
树上吊牌: [{"key":"app:star"},{"key":"app:home"},{"key":"app:map"},
          {"key":"app:group","cn":"群聊"},{"key":"app:diary"},
          {"key":"app:roster"},{"key":"app:stk"}]
群聊吊牌 key = app:group ← 改前是 app:chat
点它 → {"gcOv":true,"gcCls":"gcwrap on","title":"群聊"}   ← 群聊层，不是单聊页
```
